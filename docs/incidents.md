# Incidents

Failures that changed how the system is built, generalised, one row each. Each left a rule, a scorer, a guard or a test behind. Dates are when they happened. Most of what they left behind lives in the private system; where a public counterpart exists, the row links to it.

| # | Date | What happened | Root cause | What it left behind |
|---|---|---|---|---|
| 1 | 2026-06-13 | The morning and weekly briefs kept surfacing an item I had already closed. | The fact was copied into several files with no single owner; the brief read the stale copy. | Canonical ownership; the reconcile pass that opens the owning file first; the `stale_leak` scorer in [agent-eval-gates](https://github.com/dyjhhh/agent-eval-gates/blob/main/evals/scorers.py) with a case from this brief. |
| 2 | 2026-07-05 | A session was suspected of following instructions embedded in an uploaded PDF. A later review of the transcript found no attacker payload. | Nothing separated file content from instructions, so the suspicion could not be ruled out quickly. | The untrusted-content doctrine; [pdf-screen.sh](https://github.com/dyjhhh/agent-security-hooks/blob/main/security/pdf-screen.sh); the [deny hook](https://github.com/dyjhhh/agent-security-hooks/blob/main/security/hook-security-deny.sh) as the deterministic last line. |
| 3 | 2026-07-17 | A news card fabricated a background for me and its apology inflated the numbers further. | Claims about the operator were not grounded in the canonical facts file. | The `identity_error` scorer in [agent-eval-gates](https://github.com/dyjhhh/agent-eval-gates/blob/main/evals/scorers.py); a grounding rule that operator facts come only from one file. |
| 4 | 2026-07-18 | "Should be fine now" was said three times in one week about the same thing. | Conclusions were pre-paid before an acceptance artifact existed. | The `anticipatory_claim` scorer in [agent-eval-gates](https://github.com/dyjhhh/agent-eval-gates/blob/main/evals/scorers.py); the "deployed, acceptance point is X" form. |
| 5 | 2026-08-26 | The morning brief did not arrive, and the pipeline reported success. | Done was defined as "the job started". | Goal cards with a machine-checkable done-when; delivery receipts. |
| 6 | 2026-08-29 | Two skills were injected twelve seconds apart into one session; the second prompt landed mid-turn and was lost. The pipeline marked both delivered. | Log modification time was the delivery proxy; the fixed pause between injections was a guess. | Receipt files written only after a confirmed send; `wait_atlas_idle` in [agents/weekly-brief.sh](../agents/weekly-brief.sh) polling the pane's working indicator. |
| 7 | 2026-08-29 | A new session of the always-on agent produced a news format three versions old. | A hook had an inlined copy of the contract; the canonical file had moved on. | The single-source-is-citation rule (principle 3 in [principles.md](principles.md)); a private drift guard that fails when contract text appears outside its owner. |
| 8 | 2026-08-26 | The always-on agent was restarted every fifteen minutes for a day. | The watchdog's process pattern no longer matched the agent's command line, so a healthy agent read as dead. | The pattern fix across five scripts; a private self-test that checks the checkers. |
| 9 | 2026-09-02 | GitHub, cloud storage and a third external service all became unreachable from the mini while other hosts worked. | 21,267 kernel TIME_WAIT entries that never expired, against 16,384 ephemeral ports. Only a reboot clears it. | A red line in the private cron audit; the suppression condition in the private alert gate, reimplemented as a synthetic demo in [agent-reliability](https://github.com/dyjhhh/agent-reliability); a private sync bridge as a bypass. Written up in the [operations notes](https://github.com/dyjhhh/agent-reliability/blob/main/docs/operations-notes.md). |
| 10 | 2026-09-02 to 09-12 | A reboot recovery script never ran once in ten days and nobody noticed. | `flock` does not exist on macOS; the lock line exited zero silently. | `mkdir` locks everywhere; the incident line in every new script that takes a lock. |
| 11 | 2026-09-12 | A healthy agent was killed by its own recovery script. | `pgrep -f` matched the tmux `sh -c` wrapper, so one agent counted as two. | Count real binaries by command prefix; the recovery script never kills. | 12 | 2026-09-12 | A weekly calibration run did all its analysis and wrote no report. | Headless print mode kills background tasks at 600 seconds; the run had opened a subagent. | Headless prompts carry the single-pass, no-subagent, no-background constraints; unfinished analysis is resumed from disk. |
| 13 | 2026-09-12 | Four commits from a loop never reached the remote and the mini ended up in a detached HEAD. | `git push -q` swallowed a non-fast-forward rejection; a file copied over the sync channel conflicted with a tracked file. | Push exit codes are checked and logged; deploy to the second machine only through git. |
| 14 | 2026-09-11 | A news card was blocked for saying a company "fixed" something, when it was quoting a regulator quoting the company. | The done-claim scorers judged every done phrase as the agent's own. | Reported-speech exemption by match position in `claim_done_grounded` and `anticipatory_claim` ([scorers.py](https://github.com/dyjhhh/agent-eval-gates/blob/main/evals/scorers.py)); three regression cases. |
| 15 | 2026-09-17 | The hourly mail job sent the operator the literal string `Error: Reached max turns (5)` as that morning's summary. | The output check knew auth and rate-limit failures but not the runner's own error text. | A notification guard that treats a runner's error text as a failed run, with tests; the public version is [notify-guard.sh](https://github.com/dyjhhh/agent-reliability/blob/main/guards/notify-guard.sh). The same check had been fixed once before, on 2026-08-29, in another job, and never copied to this one. |
| 16 | 2026-09-17 | A twice-daily monitor died at its 900s wall twice running, and paged the operator both times for one transient failure. | The work had grown while the wall stayed fixed, and the job's own ping duplicated a watchdog that already alerted through the central gate. | Wall raised, prompt time-boxed, ungated duplicate deleted. |
| 17 | 2026-09-17 | One job barged in on another mid-run; both slowed and the first died at its wall. | The lock waited 300s before barging while its holder's own timeout was 900s, so concurrency was guaranteed, not racy. | Barge-in patience must exceed the longest timeout any holder can legally take. |
| 18 | 2026-09-21 | A new check for private agent codenames flagged every healthy line and passed a tree that carried them. | The generator rewrites those codenames wherever it finds them, including inside the check itself. | The pattern is built from fragments the generator cannot match. A detector cannot be written in a form its own subject rewrites. |
| 19 | 2026-09-15 to 09-21 | An earlier public snapshot of these repositories contained personal operational detail that the sanitizer should have removed. | The sanitizer matched only an enumerated list of terms and read only English, and one detector in the published scanner failed silently instead of failing the build. | The repositories were made private within the hour of discovery, the life-operations skills were withdrawn and replaced with two synthetic contracts, the publish step now refuses any unreviewed line or broken detector, and the repositories were republished with fresh histories. |
| 20 | 2026-09-21 | A private codename went out glued to underscores (`<NAME>_MODEL`, `<NAME>_TMUX_SESSION`, `wait_<name>_idle`) across six files after the rename was believed complete. | `\b` and `grep -w` define a word over `[A-Za-z0-9_]`, so a name glued to an underscore is mid-word to both; in Python's unicode mode, so is a name glued to a CJK character. | Boundaries are written explicitly on both sides of the pipeline; the same class of miss covered names prefixed with a CJK character in one hook. |

Two smaller ones from the same week, kept because they are the same family. A weekly health line reported the mini's uptime as twenty thousand days: a greedy regex on `sysctl kern.boottime` bound to `usec` instead of `sec`. A merged batch of twelve short receipts was blocked as one over-long card: the hook measured the message, the contract measured the card.

Three red alerts from the same day were measurement artifacts, not failures. launchd creates a job's stdout file at load and leaves it empty forever for a job that prints nothing when healthy, so the auditor read that phantom mtime as "last run" and reported a job firing every 180 seconds as 109 hours dead. And a calendar job cannot be late for an appointment it has never had: one whose schedule was installed more recently than a full period ago was flagged daily, with no action that could ever clear it. Verified in the direction that matters: a synthetic genuinely dead job fed to the corrected auditor still came back flagged, so it had not simply been made blind. The auditor is private; [schedule.py](https://github.com/dyjhhh/agent-reliability/blob/main/schedule.py) in agent-reliability reimplements these rules as pure functions, with tests on synthetic jobs.

The family name for most of these is in [principles.md](principles.md), rule 2: a cheap intermediate signal was allowed to carry the most expensive conclusion.
